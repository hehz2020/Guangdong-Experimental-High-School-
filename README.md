# 广东实验中学（荔湾校区）3D 校园漫游

**状态：开发中，非官方复原，与学校无隶属关系。**

## 这是什么

一个在浏览器里以第一人称行走或飞行的校园三维模型（three.js r187，原生 ES 模块，不用打包工具）。所有几何体、贴图、树木和文字都是页面载入时由代码生成的；仓库里没有照片、图片或模型文件。

依据是一张斜拍的卫星拼图、三段航拍视频的截图和一张校门照片。这些资料都不在仓库里，仓库只保存从中得到的数字和文字说明。

### 方向的变化（请先读这一段）

最初的目标是“尽量如实的简化复原”。后来先做了一块写实小样（校门和门后的水池）。项目所有者认可了这块小样，并要求把整个校园和各栋楼的室内都做到同样的完成度，“当作一件艺术品”来做：不要求百分之百符合事实，没有参考资料的地方由制作者自行想象补全。

所以现在的模型是两层东西叠在一起：

- **量测得到的布局**：建筑的屋顶轮廓和位置、田径场、校内道路、河涌、树冠的位置。楼高不是量出来的，是估的。
- **大量想象出来的细节**：门后的水池、河涌的护岸和栏杆、路缘和路灯、长椅和宣传栏、围墙、校园外的整座城市、飞机的样子、全部室内陈设，等等。

读的时候请这样区分：

1. “量测的部分”一节列出的，是从卫星图或视频里量出来、估出来的，准确度写在那里。
2. “照着照片和视频做的外观”一节列出的，是有参考资料、照着画的；尺寸多半只是按画面比例估的。
3. 其余一切都是想象的，“想象的部分”一节按区域列出了主要内容。**没有在前两节里出现的东西，请一律当作想象。**

每个生成器文件（`src/world/builders/`、`src/world/extras/`）顶部还有一段英文说明，分开写了参考里看得到的（SEEN）、假定的（ASSUMED）和想象的（IMAGINED）。

## 运行

仓库已包含运行所需的全部文件，无需安装依赖，页面也不访问任何外部网络。用任意静态文件服务器打开即可：

```
npm start          # 等价于 python3 -m http.server 8080
```

然后访问 `http://localhost:8080/`。载入要等几十秒：贴图、模型和着色器都是在浏览器里现算的。

| | 电脑 | 手机 / 平板 |
|---|---|---|
| 开始 | 点击画面（锁定鼠标） | 点一下屏幕 |
| 移动 | W A S D 或方向键，Shift 跑，空格跳 | 左下摇杆，「跑」「跳」按钮 |
| 转向 | 鼠标，Esc 释放 | 在画面上滑动（摇杆和按钮以外的地方都可以） |
| 航拍模式 | F 切换；朝视线方向飞，空格上升，C 下降，Shift 加速 | 「航拍」按钮；「跳」为上升，「跑」为加速；没有下降键，要下降只能低头往前飞 |
| 直接前往某处 | 底部「地点」（先按 Esc） | 底部「地点」 |

漫游从校门前开始，默认时间是上午 9 点多（太阳在东边，照亮校门正面）。上方滑块调整时间，右上角是小地图（北在上）。在航拍模式里关掉航拍会落到正下方的屋顶或地面上；如果落进了走不出去的地方，再开航拍飞出来即可。「地点」菜单现有 19 项：16 个地面地点（包括二层教室、体育馆内、图书馆）和 3 个空中机位。校名墙朝北、位置高，从「航拍：校名墙」看最清楚。

### 加载过程

打开页面后先是加载界面：所有贴图、模型和着色器都要在你的电脑上现算，通常要 30 秒到 1 分多钟（没有在真实显卡上量过；
无显卡的 Windows 云主机上是 45 秒）。界面会逐行显示正在做什么和已用秒数（搭建楼宇 → 布置场地和周边 → 处理材质 →
准备光照 → 建立碰撞检测 → 编译着色器并绘制），全部画完才出现“点击画面开始”。为了不让第一帧一次编译所有着色器，
场景是分批点亮的。加载出错时，原因和停在哪一步会直接写在界面上；界面还会显示“绘图设备”，如果浏览器没有用显卡绘图
（硬件加速被关掉），会有黄色提示——那种情况下能运行，但每帧要以秒计。

### 画质、性能和安全模式

- **光照**：按时刻计算太阳方位（纬度取广州，太阳赤纬固定取 +12 度，相当于 4 月下旬或 8 月中旬）。阴影用三层嵌套的阴影图（视点周围 26、91、320 米，电脑上每层 2048 像素，最近一层约 2.5 厘米一格），只在视点走出内圈或时间变化时重画。天空随时间变化，并被采样成环境光；傍晚以后窗户和灯具发光，路灯下的地面有一圈光，走到屋顶下会有室内灯光。电脑上默认开启环境光遮蔽和泛光，触屏设备默认关闭。
- **性能**：同一材质的几何体合并绘制；教室家具、走廊设施等分三档，只在走近时显示；场地上的树离视点远时换成叶片较少的树冠。触屏设备默认降低像素密度和阴影分辨率，并略去电脑上才有的表面颗粒。
- **自动画质**：页面会监测自己的帧时间，持续低于每秒 24 帧时依次关闭后期效果、降低像素密度，并在屏幕上提示。它不会降低阴影和细节的开销。
- **安全模式**：阴影和窗户发光要改写着色器代码，而这些从未在真实显卡上跑过。如果有着色器编译失败，页面会自动以 `?safe=1` 重新载入一次，只用 three.js 原装着色器：没有阴影、窗户发光、天空环境光、后期效果、抗锯齿和灯下光圈，水池是一块普通的反光面，没有喷泉。

### 一键启动程序（可选）

不想装 Python 的话，可以把整个站点编进一个可执行文件。`launcher/` 里是一个只用 Go 标准库写的小程序（一百多行）。

- **构建**：`sh launcher/build.sh` 把当前的 `index.html`、`src/`、`vendor/` 嵌进去，生成 Windows（`.exe`，x64 和 ARM64）、macOS（Apple 芯片和 Intel）和 Linux（x64）的版本，放在 `launcher/dist/`。需要 Go 1.20 以上，不下载任何依赖。`launcher/dist/` 和构建时的临时副本 `launcher/site/` 都不进仓库。
- **它做什么**：双击后只在本机 `127.0.0.1` 上提供这些文件（默认端口 8080，被占用就换一个空闲端口），不安装、不写盘，别的机器访问不到；关掉它的命令行窗口即退出。它不带浏览器，画面仍由你电脑上的浏览器渲染。Windows 上如果在常见位置找到 Chrome 或 Edge，会开一个没有地址栏的独立窗口（`--app` 方式）；否则，或者加了 `-tab` 参数，就用默认浏览器开一个标签页。macOS 和 Linux 上用默认浏览器。
- **没有数字签名**：Windows 首次运行会弹出“已保护你的电脑”的提示，需要点“更多信息 → 仍要运行”。

**Windows 版的检查。** `.github/workflows/windows-launcher.yml` 在 GitHub 的 Windows 云主机上检查它。`launcher/` 或这个流程文件有改动时运行，也可以手动触发；站点更新后想重跑，改一下 `launcher/BUILD`。流程是：在 Windows 上用同一版本的 Go（1.24.7）重新构建并打印 SHA-256；启动 exe，检查它返回的首页和几个脚本文件的状态和文件类型（`.js` 必须是 `text/javascript`）；用主机上的 Edge（启动不了就用 Chrome，无头）从它完整加载页面并截图；再不带参数启动一次，查看它是否开出了独立窗口。

- 2026-11-18 的一次运行（提交 `3dfe5c1`）全部通过：就绪用时 35 秒，没有构建失败和控制台报错，没有掉进安全模式，双击方式用 Chrome 的 `--app` 窗口打开了页面；Windows 上构建出的 exe 与在 Linux 上交叉编译的逐字节相同。
- **没有验证的**：云主机没有显卡，用的是 Windows 的软件渲染（Microsoft Basic Render Driver），真实显卡上的画面和帧率没有测过；没有人实际操作过；系统的“已保护你的电脑”提示和杀毒软件的反应测不到。
- macOS 版只是交叉编译出来的，**从未运行过**。Linux 版试过：文件类型正确，只监听本机，无头浏览器能从它完整加载页面。

## 量测的部分，以及量得多准

### 两个前提

1. **卫星图是斜拍的。** 影像从北偏东方向拍摄，屋顶在图上相对地基向南偏西位移，每米高度约 0.55 米（2.0 像素）。因此图上量到的是屋顶轮廓，地面位置要按楼高反推。这个系数由一次独立的第二遍量测重新标定：在东侧两栋教学楼北立面的四段上，从女儿墙顶到二层楼板线是 33 至 35 像素，楼层线间距 7.4 至 8.0 像素。直接量到的其实是“五层楼的屋顶位移约 41 像素”；把它拆成楼高和每米位移，仍然依赖假定的 3.9 米层高。最初用的系数是 2.3（来自一条约 47 像素的立面带，其中包含了底层以下一段范围靠猜的暗区），偏大约 15%，使所有楼的地面位置偏北 1 至 2 米，现已改正。
2. **所有楼高都是估计值，没有任何实测高度。** 依据因楼而异，逐条记在数据文件里：东侧和西侧教学楼的层数来自视频画面，层高假定 3.9 米；板楼是在卫星图北立面上数出的 6 条楼层线，层高假定 3.3 米；钟楼的 41 米来自一帧视频的相机反算（并依赖“教学楼女儿墙高 20.7 米”这个假定）；体育馆和看台屋顶按画面比例估为 15 米；新综合教学楼的 6 层来自一份规划文件；几个小楼的高度是直接假定的。同一个总高度，生成器内部可以按别的层高来分层。高度估错会连带影响地面位置：20 米高的楼，高度每错 1 米，位置约错 0.6 米。

`src/campus-data.js` 中每个条目的 `positionAccuracyM` 已把读图误差和斜拍校正的不确定性合并进去：38 个条目在 ±0.9 至 ±2.8 米之间，中位数 ±2 米。周边建筑的误差记在 `data/context.json` 里，±2.5 至 ±6 米。这些都是制作者自己估的误差，没有任何实地核对。

**载入时对树的增减。** `landscape.js` 在载入时会再处理一遍这 700 棵树：略去 132 棵，保留 568 棵（104 棵在校门一带，那里由校门模块自己种树；14 棵离建筑轮廓不到 1.8 米；7 棵在现在的道路或人行道上；其余在连廊旁、围墙线上和飞机、升旗台的位置）；树冠会被缩小到碰不到最近的建筑轮廓；另外在没有任何数据的地带种了 170 棵想象的树（见“想象的部分”）。场地模块一共画 738 棵。这些数字是用一个不启动浏览器的脚本按当前代码数出来的，没有在画面里核对；校门一带、各楼生成器自己种的树和城市里的行道树不在其内。

**第二遍独立量测。** 另一位读图者重读了 21 个主要轮廓（教学区、体育馆、看台、板楼、弧形楼、圆顶楼、球场），读数是在打开数据文件之前记下的（其中体育馆、看台屋顶、网架、西教学楼、圆顶和跑道几项，它事先在别处见过旧读数）：14 个与原读数一致（多数相差 1 至 5 像素），7 个有出入，现已全部处理：5 个按第二遍读数改了数据；弧形楼屋顶的断面（外侧约 9.1 米实板、5.2 米一排洞口、内侧 4.3 米实板）写在生成器里，数据里的条带没动；钟楼由另一次专门的定位重新确定了位置（均见下文“中途更正过的事实”）。**没有独立复核的**：东侧教学楼东南角的两个三层小楼和东北角的 L 形小楼、连廊北端的小屋顶、板楼东端的两个连接体、西教学楼东端的窄条、新综合教学楼、地面多边形和全部周边建筑；西教学楼西端的玻璃楼梯塔是原读图者自己重读的，钟楼旁的玻璃楼梯间的范围来自一帧视频的相机反算，都不算独立复核。架空连廊不在这 21 个之内，但第二遍量测逐行描过它，与原读数一致。

**可信度怎么记。** 数据里 `confidence` 一栏多数是两种固定写法：“confirmed in video”（视频已证实，18 项）和“seen in satellite only”（仅卫星图可见，是否属于学校、作何用途未证实，13 项），其余 7 项各有一句专门的说明；是否只读过一次、有没有被第二遍量测复核，记在 `measuredBy` 里。

### 仍然没有定论的地方

- **三栋教学楼的南墙线**（两栋板楼的北条也是同样的情况）。卫星图上屋顶南侧有一条明亮的女儿墙线，再往南 2 至 3 米还有一条较暗的窄带，数据取的是窄带外沿（屋顶进深约 13 至 13.6 米）。如果墙其实在女儿墙线下面，这些楼南侧就深了 2 至 3 米。从图上分不出来，视频也看不到南面。
- **新综合教学楼**的轮廓是在卫星图上单次读出的。图上该处是一个五边形的楔形屋顶，带三角形天井，西北侧有一条陶红色的条带，与 2022 年视频里新楼的屋顶相符（本次修订对照了卫星图的裁切和视频第 58 帧）。数据文件里原有的一句“卫星图早于这栋楼”与此矛盾，已改；影像的拍摄日期没有核对。它的 6 层来自一份规划文件，是本项目唯一有官方来源的层数，但仓库里没有记下是哪一份文件。
- **钟楼**的位置是重新定位过的，把握中等：数据里记的位置误差是 ±2.3 米，东西向的进深最不确定。高度约 41 米（±3 米）。塔头在挑台上的东西位置、西面那个浅色圆盘是什么，都没有查明。
- **校名墙的位置和高度。** 视频显示校名高出北教学楼屋顶，据此把字墙画到 26.4 米，立在连接体的北沿。但视频的另一帧里，这面墙向西接着北教学楼南侧的高女儿墙，所以它更可能立在北教学楼屋顶的东南角，比现在的位置偏北约 3.7 米；没有改。
- **看台**的高度（屋顶 15 米、座席顶 5 米）是按画面比例估的，实物看起来更高：生成器的说明里估计主楼接近 21 米，座席大约高一半。
- **体育馆屋顶西侧约 10 米**在图上比其余部分低 6 至 8 米（第二遍量测的读数）。
- **东侧教学楼西段的屋顶边线**在卫星图上比东段偏南约 2.8 米。是立面后退还是女儿墙更高造成的，从视频里判断不出来。
- **南端那栋高层（约 75 米）只在卫星图上有。** 图上它的北立面有约 150 像素长、方向与斜拍完全一致的竖线，所以按 75 米建了；但 2018 年视频朝那个方向看是空的天。要么它是 2018 年 9 月之后建的，要么是读图有误。它从全校园都看得到，如果不对会很显眼。
- **校园边界没有确认。** 南端和北区的建筑哪些属于学校不清楚；西北角的网球场和新综合教学楼以北的一块硬地球场是否属于学校也不清楚（后者没有建）。看台以西在卫星图上是工地，建成了什么不知道。

### 中途更正过的事实

- 跑道是标准 400 米（最初按卫星图误读为不足 400 米：南弯道在树影里）。
- 卫星图是斜拍的，最初量的屋顶轮廓被当成了地面轮廓，已全部校正。
- 斜拍系数由每米高度 2.3 像素改为 2.0 像素（见上文前提 1），所有建筑随之南移约 1.7 米。
- 看台座席是蓝、红、绿三段，不是全蓝（把 2022 年画面里的蓝色遮阳棚误认成了座席）；座席比最初量的长 8 米（原来的南端其实是一道树影的边缘），三段几乎等长。
- 西侧教学楼进深约 13.6 米、长 47.8 米，不是 17 × 51 米：最初把图上屋顶北侧带楼层线的暗色条带（其实是北立面）当成了屋顶，北边线因此偏北了 9 米。它的玻璃楼梯塔在西端南侧，不在东端；楼梯塔的北边线南移了 3.3 米。
- 教学楼西侧的连廊不是 4 米高的平地连廊，而是约 7.8 米高的架空走道。
- 网架顶棚东南角那块蓝灰色不是缺口，是钟楼的影子；顶棚南沿多出 2.1 米。
- 体育馆整体东移 1.9 米；圆顶中心南移 1.9 米。
- 东侧教学楼两端楼梯塔的高度由 23.5 米改为 21.5 米（视频里塔顶板只比教学楼女儿墙高约 0.8 米）。
- **钟楼向南移了约 6.4 米。** 原来记下的那个方块其实是玻璃楼梯间屋顶上的浅色构件，不是钟楼。新位置有三条依据：对 2018 年视频一帧做相机反算，塔身整个在网架南沿以南；卫星图上一条细长的亮带是玻璃楼梯间顶部和塔身下段被太阳照亮的东立面；按图上的太阳方位，41 米高的塔的影子正好落在网架屋面东南角那块蓝灰色斑上。钟楼紧贴玻璃楼梯间南面，离南教学楼西端约 6.5 米，中间是连廊。
- 钟楼旁的玻璃楼梯间比原来记的大：约 7 × 8.4 米，玻璃顶约 24 米。
- 新综合教学楼最初的轮廓向西北多出 4 至 8 米（把阴影里的立面当成了屋顶），高度由 25.2 米改为 23.4 米。

### 数据文件和生成脚本

- `data/measurements.json` 是原始读数；`npm run data` 由它生成 `src/campus-data.js`。这一步读者可以自己重跑。
- `data/context.json`（周边建筑）和 `data/landscape.json`（树、地面、道路、河涌）分别由 `scripts/make-context.py` 和 `scripts/make-landscape.py` 生成，同样的数字还写在 `src/world/extras/context.js` 和 `landscape.js` 里两段标了记号的数据块中。**这两个脚本需要卫星拼图（不在仓库里）和 Pillow，读者无法在仓库里重跑**：

  ```
  python3 -I scripts/make-context.py <仓库目录> /path/to/campus_z19.jpg
  python3 -I scripts/make-landscape.py /path/to/campus_z19.jpg
  ```

  本次修订在仓库的一份副本上各跑了一遍，输出与仓库里的文件逐字节相同。这两个 JSON 文件运行时并不读取，只是供人查阅的记录。
- **生成出来的文件里有几句过时的话，不能手改，只能等下次带着卫星图重新生成时一并改掉**：`data/landscape.json` 的说明和 `scripts/make-landscape.py` 的注释里仍写着“卫星图早于新综合教学楼”；`data/context.json` 里南端高层和北区一栋楼的可信度说明里也有同样的话（见上文，这个说法很可能不对）；`data/landscape.json` 只写了 700 棵树，没有写载入时的增减。
- 数据文件的 `measuredBy` 和备注里有一些制作过程中的代号，指的是不同的读图或建模环节，不是人名，更不是测绘单位：main session 是最初的读图者，也是汇总数据的一方；measurement agent（后面括号里是 east-slabs、dorms、courts）是分片区读图的另一方；independent second reading 是上面说的第二遍独立量测；tower-location agent、plaza agent、modelling agent、landscape agent 是按任务命名的其他环节。
- 文中和代码注释里的“第 N 帧”，以及数据里 `frames_…`、`shots/…` 之类的路径，指的是制作时从视频里抽出的截图和临时文件，都不在仓库里，读者无法对照。

## 想象的部分

以下内容没有任何参考资料支持，是为了让画面完整而想象的。

**校门和水池**

- 所有尺寸。
- 水池本身：只知道门后有一个水池，形状不知道。圆形水池、池中刻着校训的景石、一圈喷泉、池前的弧形花台都是想象的。景石上的“爱国 团结 求实 创新”是学校公开的校训，但“刻在这块石头上”是编的。

**场地和河涌**

- 每一棵树的样子（只有一种通用的阔叶树）和高度。
- 绿化带：量测范围和外围城市之间的地带（主干道沿线、看台以西、田径场西南）没有任何数据，画成了草地，并按 13 米的网格种了 170 棵树。看台以西在卫星图上其实是工地。

- 围墙：河涌边那条路西侧的砖柱铁栏杆围墙。真实的围墙在哪里不知道，其他几面没有画。
- 网球场：按标准尺寸画的两块场地、球网、裁判椅和铁丝网围栏。
- 田径场：跑道上的全部标线和道次数字、100 米起跑用的直道延长段、内沿的道牙和排水沟；足球场（68 × 105 米）和它的标线、修剪条纹、球门、角旗；铅球区、栏架、长凳。

## 已知问题

**行走**

- 在航拍模式里退出，可能落进走不出去的地方。较早的质检找到过：带女儿墙的屋顶（东侧两栋教学楼、网架北侧的白色方楼）和球场南侧院落式建筑的两个天井；教学楼重做以后没有复查。再开航拍即可飞出。
- 从岸上走不进河道（两岸各有一道挡板，同时也是河道的侧壁）。如果在河涌上空退出航拍，会落到河床上（比岸低 2.6 米），头刚好露出水面，四面都是河壁，要再开航拍飞出来。主干道桥下那 14 米河道在碰撞里是实心的，走不进去。
- 碰撞是单面的：落进一栋封闭的楼里以后，可以从里面穿墙走出来。
- 只有靠近铺地或道路的树干有碰撞（现在是 156 棵）；其余树干、绿化带里想象的树和所有树冠都可以穿过。
- 跳起来能越过 1.1 米高的栏杆。这个问题只在看台、东侧教学楼外廊和西侧教学楼处理过（隐形挡板加到 1.7 米）；看台和东侧教学楼后来重做了，其他地方的栏杆从未逐一检查。
- 走到离原点 680 米处会被挡住，那里是模型的边缘。
- 钟楼南侧的铁梯只是摆设，走不上去（它从钟楼西侧那栋楼的屋顶起步）。架空连廊现在能走上去。

**画面**

- 树避让数据里的屋顶轮廓，以及生成器主动上报的、建在轮廓以外的部分。目前只有看台南翼上报了（原先长在南翼墙里的两棵树已不再画出，看过俯视图）；其他楼如果在轮廓外加建了东西而没有上报，树仍可能长进去。
- 分别建的几个体块在平面上有重叠（圆顶楼与弧形楼、连接体与旁边的小楼、西教学楼与它的玻璃楼梯塔等）。较早的质检没有看到闪烁；这几栋楼之后有的重做过，没有复查。
- 较早的质检发现：视点正好在地面网格的一个顶点上方、视线水平时，软件渲染会把整片地面画成一种颜色，「操场中央」这个地点每次都会碰上。之后把网格错开了；别的位置是否还会出现没有复查，真实显卡上是否出现不知道。
- 小地图画的是屋顶轮廓反推到地面的多边形，不是实际建出来的范围：看台南翼、弧形楼内侧、新综合教学楼的门厅（比轮廓向南多出约 3 米）都比图上画的大（较早的质检量的，看台之后重做过）。小地图的范围（x −115 至 320、z −290 至 245）也比能走到的范围小。
- 「图书馆二层回廊」这个地点的视角不好（较早的质检）。「钟楼下」面前原来挡着一棵树，已经清掉；但这个视角从南面仰看塔身，看不到表盘（表盘在西面和东面）。
- 钟楼西侧那栋五层楼的底层画成了架空的柱廊。没有任何参考能看到它的底层，这样画是为了不堵住从南面进网架广场的路；实际可能是封闭的。
- 广场东北角的弧形台阶和一个暗红色门框（2018 年视频里看得到）没有做。
- 页面标题和 `package.json` 的描述里没有“非官方”字样；开始面板和左下角的提示里有。触屏设备上左下角的提示 15 秒后会自动隐藏。

**手机和平板**

- 没有下降键（见上文操作表）；竖屏时帮助面板会压到小地图下面，横屏时摇杆会盖在打开的帮助上（较早的质检，设备模拟）。
- 带触摸屏的笔记本电脑上，页面会按触屏设备处理：出现摇杆，开始面板显示触屏的提示。这一条是按代码读出来的，没有试过。
- 既没有鼠标也没有触摸屏的设备上转不了视角，开始面板会这样提示。

**性能**

- 走动时每隔几米要重画一次近处的阴影图，那一帧的绘制量在较早的版本上量过，是平常的 1.5 至 2.2 倍；之后场景重了很多，没有重新量。真机上是否表现为卡顿不知道。
- 自动画质只会关闭后期效果和降低像素密度，手机上后期效果本来就是关的，所以它在手机上只能降像素密度。
- 较早的版本在无头软件渲染里，抗锯齿与阴影同时开启时控制台会出现图形驱动的性能提示（`GPU stall due to ReadPixels`），不是错误。成因未查明，真实显卡上是否出现不知道。

## 校验用的网址参数

- `?start=地点名`：从校门模块提供的某个地面地点开始（「校门」「校门内 · 水池」「水池西侧（回望校门）」，默认「校门」）；`?start=field` 从田径场草皮南端开始。
- `?time=9.2`：时刻（小时，默认 9.2）。
- `?view=top`：正上方俯视（北在上），可加 `&w=&e=&n=&s=` 指定范围（米）；`?view=overview`：斜俯视，可加 `&cx=&cy=&cz=&tx=&ty=&tz=` 指定相机位置与目标。
- `?flat=1`：实体轮廓以纯色无阴影绘制。
- `?quality=low|high`：画质（`high` 同时视为不要自动降画质）；`?adapt=0|1`：关闭或强制开启自动画质（自动化浏览器里默认不启用）。
- `?post=0|1`：关闭或强制开启后期效果（`post=1` 同时视为不要自动降画质）；`?aa=0`、`?shadows=0`：关闭抗锯齿、阴影；`?cascades=1|2|3`：阴影层数；`?shadowres=1024`：阴影图边长；`?env=0`：不采样天空，改用简单的半球光；`?grain=0`：关闭电脑上的表面颗粒。
- `?safe=1`：安全模式（见上文）。
- `?ui=0`：隐藏界面。
- `?only=编号,编号`：只生成指定的建筑条目（同时略去场地、球场等附加模块，加 `&extras=1` 保留）。
- 开发用：`?try=样式:文件.js`、`?tryx=文件.js` 临时挂载 `src/world/builders/`、`src/world/extras/` 里未登记的模块；`?lightdebug=1` 把光照模块挂到 `window.__lighting`；`?gymdebug=1` 把体育馆的调参对象挂到 `window.__gym`。
